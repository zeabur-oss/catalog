---
title: Differences between Kubernetes distributions
description: Compare known differences between Kubernetes distributions and check the settings that components and templates need.
---

Components and templates are tested on kind with the same Kubernetes minor version as the RKE2 version pinned by Zeabur Installer. The `single-node` profile uses 1 node, and the `multi-node` profile uses 3 nodes. Each profile groups the settings for its deployment layout. Components are also tested on k3s, RKE2 and KubeSolo, installed on the runner (see [Tests and CI](../contribute/tests.mdx)). Other distributions behave the same, with the following known differences.

- **k3s**: Add `--disable=traefik,metrics-server` at startup so that each component's chart installs Traefik and metrics-server. k3s installs its own Gateway API CRDs. When running behind NAT, don't set `node-external-ip`, or Traefik will lose the client address.
- **KubeSolo**: The default StorageClass retains volumes and their data after you delete a PersistentVolumeClaim. On Ubuntu, map the hostname in `/etc/hosts` to the node IP. If it maps to 127.0.1.1, the API server will refuse to proxy connections to the kubelet. KubeSolo nodes don't have a control-plane label.
- **Longhorn**: Each node needs open-iscsi installed, `iscsid` running, the `iscsi_tcp` module, and an NFSv4 client. Don't let multipathd manage disks that Longhorn uses. See the comments in the Longhorn component file for detailed requirements. Longhorn doesn't run on KubeSolo.
- **Distribution limits**: A component's `distributions` field lists the only distributions it can run on, for a hard limit such as a node label that other distributions don't set. For example, system-upgrade-controller runs only on k3s and RKE2. The e2e tests on k3s, RKE2 and KubeSolo skip a component whose list leaves out that distribution. The distributions a component passed on are its `testedOn` in `index.json`.
- **Template storage**: Templates don't specify a StorageClass, so volumes use the cluster's default StorageClass. If the cluster has no default StorageClass, PersistentVolumeClaims remain `Pending`.
