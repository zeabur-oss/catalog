title: Component file format
description: Write YAML with the shared envelope and component fields, and pin installation content with digests.
---

Place component files in `components/<capability>/<upstream>.yaml`, with one file for each combination of capability (purpose category) and upstream. Each YAML file contains the shared envelope, installation content, and configuration. The path determines the ID. For example, `components/ingress/traefik.yaml` has the ID `ingress/traefik`.

## Shared envelope

Components and templates share an envelope of `apiVersion`, `kind`, `metadata`, and `requires`. `kind` distinguishes components from templates. `requires` accepts a capability or `<capability>/<upstream>`.

```yaml
apiVersion: catalog.zeabur.com/v1
kind: Component                   # or Template
metadata:
  name: Traefik Proxy
  description: Why it is recommended, or what the template runs, in one or two sentences.
  license: MIT                    # SPDX
  homepage: https://traefik.io/traefik/
requires: [certificates]          # <capability> or <capability>/<upstream>
```

A component's `metadata` also has a `summary`: what it gives the cluster, in one plain sentence for people choosing components, with its translations in `locales`. Installers show the summary; the description stays for operators.

```yaml
metadata:
  summary: Routes traffic from your domains to your services.
  locales:
    zh-TW: {summary: 把網域的流量導向你的服務。}
    zh-CN: {summary: 把域名的流量转发到你的服务。}
```

## Component fields

The following example shows a minimal component. `defaults` specifies whether to enable the component for each profile (the `single-node` or `multi-node` configuration), and `recommended` means enabled by default (recommended). `releases` lists the content to install in order. Settings in `profiles` merge into the shared `values`.

```yaml
apiVersion: catalog.zeabur.com/v1
kind: Component
metadata:
  name: Traefik Proxy
  description: Why it is recommended, in one or two sentences.
  license: MIT                    # SPDX; OSI-approved, or opt-in only (see below)
  homepage: https://traefik.io/traefik/
maturity: independent             # cncf-graduated | cncf-incubating | cncf-sandbox | kubernetes-sig | independent
defaults: {single-node: recommended, multi-node: recommended}
requires: [certificates]          # installed first
distributions: [k3s]              # optional; distributions to test it on, omitted means all

releases:                         # installed in order
  - name: traefik
    namespace: traefik
    chart: oci://ghcr.io/traefik/helm/traefik   # or repo: https://… plus chart: <name>
    version: 41.7.1                             # exact; Renovate bumps it
    chartDigest: sha256:…                       # required with chart; see Digests
    values: |                                   # shared by every profile
      gatewayClass:
        # Every value has a comment saying why; `catalog validate` enforces it.
        enabled: true
      image:
        # Every image is <tag>@sha256:<digest>; `catalog render` enforces it.
        tag: v3.7.16@sha256:…
    profiles:                                   # merged over values like helm -f
      single-node: |
        deployment:
          # One node: a second replica gains nothing.
          replicas: 1
  - name: crds
    namespace: kube-system
    urls: [https://github.com/…/releases/download/{version}/standard-install.yaml]
    version: v1.6.2
    urlDigests: [sha256:…]                      # one per URL, in order
  # or: manifests: |  objects applied as written

inputs: []        # values to ask for or generate; Secrets are created from them
provides: {...}   # an in-cluster registry other software uses
resources: {...}  # memory it needs while working, on top of idle
internalCRDs: []  # CRDs of detection.crds whose objects it writes itself
networkPolicies: |  # traffic it needs where an installer isolates namespaces
contributes: []   # values added to another component's release (CrowdSec -> Traefik)
detection: {...}  # CRDs, API services, Helm charts, workloads
security: {...}   # RBAC summary, cluster-wide, privileged, podSecurity, egress, credentials, tenant risks
health: []        # read-only checks an installer runs on a cluster
smoke: []         # extra e2e checks
leftovers: []     # what the upstream keeps on uninstall (e.g. CRDs)
```

## What installers read

These fields tell an installer what a component offers, so the installer never needs to know a component by its ID.

`provides.registry` is an OCI registry in the cluster: `host` is the `host:port` images name, and `ca` is the Secret key with the CA that signs its certificate. Removing the component waits until no Pod outside its namespaces runs an image from the host.

An input with `generate: clusterIP` takes a fixed ClusterIP for a Service of the component. A node's container runtime cannot resolve the registry host, so an installer fills the input with a free address in the Service CIDR and points a registry mirror on each node there. Left empty, as in CI, Kubernetes assigns an address and only Pods reach the registry.

```yaml
inputs:
  - name: cluster-ip
    release: zot
    path: service.clusterIP
    generate: clusterIP
provides:
  registry:
    host: zot.zot.svc:5000
    ca: {name: zot-tls, key: ca.crt, namespace: zot}
```

`detection.csiDrivers` lists the CSI drivers of the volumes the component provides. Removing the component waits until no PersistentVolume uses one of them. Find the StorageClass by its `provisioner`.

Removing a component also waits for the objects of its `detection.crds` outside its namespaces, except those in `internalCRDs`: CRDs whose objects the component writes itself, such as scan reports. Every entry of `internalCRDs` must be in `detection.crds`.

`resources.workMemoryMiB` is the memory the component uses on top of its idle use while working, such as one build. Its idle use is measured in e2e and published in `index.json`.

`health` lists read-only checks that an installer such as `zeabur-installer doctor` runs on an installed cluster. Each check runs `kubectl wait` once, with the arguments in `wait` and the time limit in `timeout`. Put a `--for` condition in `wait`, and leave out `--timeout`. When a check fails, the installer shows its `advice`, which tells the reader in English what to do. A health check has no manifest and applies nothing. Put checks that create objects in `smoke`, which only e2e runs. e2e runs `health` after install and before `smoke`.

```yaml
health:
  - name: nodes-ready
    wait: ["--for=condition=Ready", "nodes.longhorn.io", "--all", "-n", "longhorn-system"]
    timeout: 60s
    advice: "A node that joined without Longhorn needs longhorn: true under join in its configuration. Add it, then run zeabur-installer apply on that node."
```

`distributions` and `testedOn` are two different lists. `distributions` in the component file names the distributions to test the component on. `testedOn` in `index.json` names the distributions where that test passed, at the versions that `config/kubernetes.yaml` pins. An installer reads `testedOn` to offer the component only where it passed. `catalog index` derives `testedOn` from `measurements/`, so don't write it by hand. It's present on every component and can be empty.

`networkPolicies` is for installers that block incoming traffic to each namespace by default. It holds standard NetworkPolicy objects in the component's own namespaces, which such an installer applies before the releases, for the traffic the component needs from elsewhere. Other installers can ignore it. `catalog validate` checks that each object is a NetworkPolicy in one of the component's namespaces.

## Pin content with digests

Every `releases` entry must pin its content with a digest. Zeabur Installer and `catalog render` stop if the chart or URL content doesn't match its digest.

- For HTTP charts, `chartDigest` uses the `digest` from the corresponding entry in the repository's `index.yaml`, which is the sha256 of the `.tgz`.
- For OCI charts, `chartDigest` uses the manifest digest, which is the value that `helm push` outputs. `helm pull <chart>:<version>@sha256:…` checks this value.
- `urlDigests` uses the sha256 of each downloaded file, in the same order as the URLs.
- Images in `values` use `<tag>@sha256:<digest>`, including images that the chart passes to an operator as arguments. If a chart doesn't accept a digest, list the image in `unpinnedImages` and explain why in a comment. URL installation entries are exempt from this requirement.

Renovate updates image and OCI chart tags and digests. It can't read digests for HTTP charts or URLs. After Renovate updates `version`, `catalog render` fails and outputs the new digest for you to copy into the file.

Installation results must be consistent: charts must not generate keys or certificates. Put values that need generation in `inputs` and store them in Secrets; cert-manager supplies certificates. If two renders produce different results, `catalog render` fails.

For the complete field definitions, see the [component JSON Schema](https://github.com/zeabur-oss/catalog/blob/main/schema/v1/component.schema.json).
