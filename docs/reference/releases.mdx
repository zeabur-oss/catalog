---
title: Releases and bundles
description: Pin a Zeabur Catalog version, verify Sigstore signatures, and read index.json, or build release artifacts from a specific commit.
---

Pushing a `vX.Y.Z` tag publishes `index.json`, `bundle.tar.gz`, `checksums.txt`, and `SHA256SUMS` with its Sigstore signature bundle. Tools that use Zeabur Catalog should pin a version and verify it before reading `index.json`.

## Release artifacts

| File | Contents |
| --- | --- |
| `index.json` | All components, their installation order and measurements for each profile, the components enabled by default (recommended) for each capability, all templates and their measurements, resource budgets, and Kubernetes versions. A profile is a configuration for `single-node` or `multi-node`; a capability is a category of use cases. |
| `bundle.tar.gz` | A bundle containing the index, cross-check data, components, templates, and related files. |
| `checksums.txt` | File checksums. |

`SHA256SUMS` lists the checksum of every other file and has a cosign keyless Sigstore signature bundle, `SHA256SUMS.sigstore.json`. Every file also has a GitHub build provenance attestation.

The shared release workflow of [zeabur-oss/.github](https://github.com/zeabur-oss/.github) signs every zeabur-oss release. A signature names that workflow, the repository `zeabur-oss/catalog`, and the tag.

## Verify and read a release

<Steps>

<Step>

### Pin a version and verify the signature

The tool first pins the version to use, then verifies the file. The following commands verify the signature of `SHA256SUMS`, then the files it lists. Download the files into a new private directory first:

```sh
tag=vX.Y.Z
cosign verify-blob SHA256SUMS --bundle SHA256SUMS.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/zeabur-oss/\.github/\.github/workflows/release\.yml@' \
  --certificate-github-workflow-repository zeabur-oss/catalog \
  --certificate-github-workflow-ref "refs/tags/$tag" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
sha256sum --check --ignore-missing SHA256SUMS
```

To check the attestation instead, run `gh attestation verify index.json --repo zeabur-oss/catalog --signer-workflow zeabur-oss/.github/.github/workflows/release.yml`.

</Step>

<Step>

### Read the index and generate installation content

After verification, the tool reads `index.json`. Only incompatible changes affect `indexVersion`.

When installing components, the tool runs `detection`, offers the components enabled by default (recommended) for the cluster's profile, and collects each component's `inputs` from the user. It then generates installation content according to `installOrder` and merges `contributes` into the corresponding targets.

When deploying a template, the tool checks that the cluster meets all requirements listed in `requires`, collects template inputs from the user, and writes the remaining automatically generated values to a Secret. It then renders and applies `manifests.yaml` for the project's Namespace.

For deployment instructions, see [Deploy a template](../get-started/deploy-a-template.mdx).

</Step>

</Steps>

## Build release artifacts from a commit

Run this command at any commit:

```sh
nix build .#release
```

As defined in `flake.nix`, the `release` output includes:

- `index.json`
- `crosscheck.json`
- `bundle.tar.gz`
- `checksums.txt`

The `bundle.tar.gz` file contains:

- `index.json`
- `crosscheck.json`
- `components/`
- `templates/`
- `schema/`
- `config/`
- `measurements/`
- `LICENSE`
- `README.md`

This command builds artifacts that are byte-for-byte identical to the release artifacts. Tools can build from an unreleased commit, then compare the artifacts with the signed release after that commit is released.
