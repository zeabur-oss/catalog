选择 capability 和上游项目，创建组件文件并完成本地检查，再提交 pull request。完成后，你会得到一个通过检查的组件文件和一个 pull request。

## 开始前

- 使用 `nix develop` 获取 Go、Helm、kubectl、kubeconform、etcd、kube-apiserver 和 kind。
- 运行 L1 和 L2 检查时，还需要 Linux 上的 Docker。

<Steps>

<Step>

### 选择 capability 和上游项目

选择 capability（用途类别），并挑选采用 OSI 批准许可证的上游项目。优先选择 CNCF 或 Kubernetes SIG 项目。

如果许可证属于 `optInOnly`（`SSPL-1.0`），每个 profile 都只能设为可选（`optional`）或 `unsupported`。

</Step>

<Step>

### 创建组件文件

参考类似的组件文件，创建 `components/<capability>/<upstream>.yaml`。

为 `single-node` 和 `multi-node` 这两个 profile（配置组合）分别指定配置值，并各加一条注释说明原因。

</Step>

<Step>

### 运行本地检查

运行以下命令：

```sh
go run ./tools/cmd/catalog validate          # schema, license, references, comments
go run ./tools/cmd/catalog render            # helm template + kubeconform
go run ./tools/cmd/catalog e2e -tier l0      # what every pull request runs
go run ./tools/cmd/catalog e2e -tier l2 <id>
```

`validate` 检查 schema、许可证、引用和注释。`render` 运行 `helm template` 和 kubeconform。每个 pull request 都会运行 L0 检查。

</Step>

<Step>

### 提交 pull request

使用 `git commit -s` 创建包含 sign-off 的 commit，再发起 pull request。

</Step>

</Steps>
