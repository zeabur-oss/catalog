description: 把一段提示粘贴到 Claude Code 或 Codex，它会用 Catalog 固定的版本和配置值安装 Zeabur Catalog 组件，每次改动前先给你看。

Claude Code 或 Codex 这类 Coding Agent 可以替你安装组件。如果放任它自己处理，它可能自行选择 chart 版本和配置值来运行 `helm install`，还会漏掉 Zeabur 开源版为组件添加的对象。这段提示让它只使用 `zeaburctl components export` 输出的内容，版本和配置值都与 Zeabur 开源版安装的相同。

## 开始前

- 在运行 Agent 的电脑上安装 [zeaburctl](https://oss.zeabur.com/zh-CN/docs/zeabur/reference/zeaburctl/) 和 kubectl，并准备能连接集群的 kubeconfig。
- 了解集群如何安装 Helm chart。由 Flux 或 Argo CD 管理的集群用 `flux` 或 `argocd`。否则 K3s 和 RKE2 内置 helm-controller，格式为 `helmchart`。其他集群用 `helm`。

## 粘贴这段提示

把[组件列表](../reference/components.mdx)中的组件 ID 填入 `<ids>`：

```text
在我的集群安装 Zeabur Catalog 组件 <ids>，按照 https://oss.zeabur.com/zh-CN/docs/catalog/get-started/agent.md 操作。
先问我要用哪个 kubeconfig context，每个 kubectl、helm 和 zeaburctl doctor 命令都指定它（helm 用 --kube-context，其他用 --context）。
问我集群适合哪种格式：由 Flux 或 Argo CD 管理的用 flux 或 argocd，否则 K3s 和 RKE2 用 helmchart，其他用 helm。
只安装 `zeaburctl components export <ids> --format <格式>` 输出的内容。不要自己选择 chart 版本、修改配置值，也不要运行输出以外的 helm 命令。
输出中每个 <名称> 占位符的值都要问我，再把我的回答填进去。
每次写入集群前，先给我看会改什么，等我同意：manifest 给我看 `kubectl diff --server-side -f <文件>` 的结果，helm 格式给我看输出中要运行的命令。
每个组件的输出末尾是“Zeabur's objects for <id>”那一段，要等该组件装好、Pod 全部就绪后再应用。
完成后运行 `zeaburctl doctor --output json`，告诉我它发现的问题。
```

要部署模板，改用 Zeabur 开源版文档中[交给 Agent 部署](https://oss.zeabur.com/zh-CN/docs/zeabur/deploy/templates/#交给-agent-部署)的提示。它会部署 `zeaburctl templates export` 输出的内容，模板需要的组件则用 `zeaburctl components export` 安装。

## Agent 会做的事

1. 问你 kubeconfig context、格式和每个占位符的值。
2. 用 `zeaburctl components export` 输出每个组件的 manifest 或命令。
3. 每个改动先给你看，你同意后才应用。
4. 组件装好、Pod 全部就绪后，应用 Zeabur 自己的对象，例如告警规则。
5. 告诉你 `zeaburctl doctor` 发现的问题。

## 你自己要做的事

- 决定安装哪些组件、使用哪种格式，以及占位符的值。
- 同意之前，先看过每份 diff。
- 由 Flux 或 Argo CD 管理的集群，可以让 Agent 把文件写入它同步的仓库，而不是直接应用。
