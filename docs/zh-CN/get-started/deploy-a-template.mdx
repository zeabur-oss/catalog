---
title: 用 zeaburctl 部署模板
description: 用 zeaburctl 导出模板的对象，检查后再用 kubectl 应用。
---

`zeaburctl templates export` 会输出将 Zeabur Catalog 模板部署到 Zeabur 开源版项目时写入的对象，与网页界面写入的相同。检查这些对象，用 `kubectl` 应用，再运行冒烟测试（smoke check）和你自己的测试。命令说明和给编程代理的提示词见 [Zeabur 开源版文档](https://oss.zeabur.com/zh-CN/docs/zeabur/deploy/templates/)。

## 开始前

- 安装 `kubectl`，以及与你的 Zeabur 开源版同版本的 `zeaburctl`。`zeaburctl` 内含 Zeabur 开源版所附 Zeabur Catalog 版本的模板。
- 阅读模板 `template.yaml` 中的许可证、输入、`requires` 和安全风险。
- 使用能落实 NetworkPolicy 的 CNI。模板不限制出站流量。
- 如果模板需要域名，先准备好 cert-manager ClusterIssuer。
- 每个项目内，同一个模板只能安装一次。模板内的对象名称固定。

<Steps>

<Step>

### 检查集群

模板不指定 StorageClass，卷会使用默认的 StorageClass。没有默认 StorageClass 时，PersistentVolumeClaim 会停留在 `Pending`。列出 StorageClass：

```sh
kubectl get storageclass
```

其中一行的名称后面有 `(default)`，例如 `local-path (default)`。如果没有，先将一个 StorageClass 设为默认再继续。

</Step>

<Step>

### 导出并应用模板

将 `<id>` 换成模板 ID，`app` 换成项目：

```sh
umask 077
zeaburctl templates export <id> --project app \
  --domain app.example.com --cluster-issuer letsencrypt --set <name>=<value> > app.yaml
kubectl diff --server-side -f app.yaml
kubectl apply --server-side -f app.yaml
```

模板要求的每个输入都用 `--set <name>=<value>` 提供。未提供的输入、缺少的 `--domain` 和 `--cluster-issuer` 会以 `<name>` 占位符出现，应用前要带上这些值重新导出。如果集群缺少模板需要的组件，`zeaburctl` 会说明，并列出安装它的 `zeaburctl components export` 命令。对象存储桶和凭据需要事先准备好。

输出的开头是存放模板自动生成的密码和密钥的 Secret。每次导出都会生成新值，所以只导出一次，并应用那个文件。再应用之后的导出，会替换运行中应用的密码。不要将这个文件加入版本控制。

确认每个 Pod 都已启动：

```sh
kubectl -n app get pods
```

几分钟内，每个 Pod 的 `STATUS` 会是 `Running`，`READY` 的两个数字相同，例如 `1/1`。已完成的 Job 的 Pod 显示 `Completed`。接着运行 `template.yaml` 中 `smoke` 列出的检查，以及你自己的测试。模板有域名时：

```sh
curl -sI https://app.example.com | head -n 1
```

第一行是 HTTP 状态行，例如 `HTTP/2 200`。

</Step>

<Step>

### 升级与回滚

记录每次部署的版本、项目、镜像引用、输入和 Secret 名称。升级前，比较导出的对象差异，阅读当前版本到目标版本之间的所有升级注意事项，完成备份，并先在复制出的环境中演练升级。

要将应用回滚到旧版，先确认数据库和存储的兼容性，再应用此前已验证版本的对象。数据库降级通常需要恢复。备份应存放在应用的项目之外。

</Step>

</Steps>

## 自动生成的输入

自动生成的输入包含 `secret`（`name` 和 `key`），以及必须匹配完整生成值的 `validation.pattern`。

| 字段 | 说明 |
| --- | --- |
| `generate.type` | `random`。 |
| `generate.bytes` | 编码前的随机字节数，范围为 12 到 64，必填。 |
| `generate.encoding` | `base64url`（不含填充字符）或小写 `hex`，必填。 |

用户提供的输入包含 `required`，不包含自动生成字段。12 个字节以 `base64url` 编码后会得到 16 个字符；16 或 32 个字节以 `hex` 编码后会分别得到 32 或 64 个字符。

CloudNativePG 会自行创建应用凭证的 Secret，模板直接沿用。
