安装工具从某个[版本](releases.mdx)读取 `index.json`，再决定安装哪些组件。本页列出选择的规则。Zeabur Installer 按这些规则选择。其他安装工具只要遵守同样的规则，同一份配置就会选出同样的组件。每条规则在 `conformance/select/` 都有一个测试用例，用法见本页最后一节。

## 安装工具需要的数据

- 一个 catalog 版本的 `index.json`。
- profile，即 `single-node` 或 `multi-node`。
- 发行版，即 `k3s`、`rke2` 或 `kubesolo`。
- 集群节点的平台，例如 `linux/amd64`。
- 用户写的 `enable` 和 `disable` 列表。每一项可以是组件 ID（例如 `victoria-logs`），也可以是 capability（例如 `logs`）。

## 名称

名称是某个组件的 ID 时，指的就是那个组件。其他名称都当作 capability，对应组件的 `provides.capability`。安装工具从提供这个 capability、在当前 profile 不是 `unsupported` 的组件里选一个。选法是按下列顺序排好，取第一个。

1. `testedOn` 在当前发行版下列有当前平台的组件排前面。
2. 然后是当前 profile `recommended` 的组件。
3. 最后按 ID 排序。

名称对不上任何 capability 或组件 ID 时，不管写在 `enable` 还是 `disable`，都会报错。

## 选择组件

安装工具按顺序执行下面几步。

1. 先取当前 profile 所有 `recommended` 的组件，这些是**默认组件**。安装工具可以用 ID 或 capability 再加上自己需要的组件，这些组件也算默认组件。
2. 加入 `enable` 列出的组件，这些是**启用的组件**。
3. 去掉 `disable` 列出的组件，这些是**停用的组件**。写组件 ID 就去掉那个组件，写 capability 就去掉这个 capability 下所有已选的组件。名称存在但没对上已选的组件时，什么都不做。
4. 去掉在这里装不了的组件，这些是**排除的组件**。每个排除的组件都要附上原因。测试用例用下表的代码表示原因，怎么向用户说明，由安装工具自己决定。

   | 情况 | 代码 | 是否排除 |
   | --- | --- | --- |
   | `distributions` 没有列当前发行版 | `distributions` | 一律排除。启用的组件另外显示 `left-out` 警告 |
   | 当前 profile 的 `defaults` 是 `unsupported` | `unsupported` | 一律排除。启用的组件另外显示 `left-out` 警告 |

   `testedOn` 没有在当前发行版下列出当前平台的已选组件，照样保留，并显示 `untested` 警告。从未在这里测试过的组件，和最近一次在这里测试失败的组件，都这样处理。
5. 按 ID 顺序遍历已选的组件，取每个组件在当前 profile 的 `installOrder`，排出**安装顺序**。`installOrder` 先列它需要的组件，最后是它自己。结果里还没有的 ID 就依次加进去。结果里没有被选中的组件，是因为其他组件需要才安装的。

   `installOrder` 里需要的组件，可能已停用、被排除或没测试过：

   | 需要的组件 | 结果 |
   | --- | --- |
   | 已停用，或因为 `distributions`、`unsupported` 排除 | 报错，代码是 `needs-disabled` |
   | `testedOn` 没有在当前发行版下列出当前平台 | 照样安装需要的组件，并显示 `untested` 警告 |

   例如 VictoriaLogs 需要 VictoriaMetrics operator，而 operator 只在 k3s 上测试过。在 rke2 上，不管 VictoriaLogs 是默认组件还是启用的组件，都会连 operator 一起装，并提示 operator 在 rke2 上没测试过。

选择的结果有三部分：

- 按安装顺序排好的组件，以及各自的安装原因：`default`、`enabled` 或 `dependency`。
- 排除的组件和原因。
- 警告。

每个 `installOrder` 都已经把组件排在它需要的组件之后，所以结果也是这样。`enable` 和 `disable` 怎么排列，都不影响结果。

## 错误

遇到下列错误时，安装工具会停下来，什么都不装。`kind` 是测试用例里的错误名称。

| `kind` | 情况 | 要告诉用户 |
| --- | --- | --- |
| `unknown` | 名称对不上任何 capability 或组件 ID | 这个名称 |
| `needs-disabled` | 已选的组件需要的组件已停用，或因为 `distributions`、`unsupported` 排除 | 两个组件的名称 |

## 安装与检查

按结果的顺序安装组件，并移除结果里没有的已装组件。每个组件的 releases、固定内容的 digest，以及安装工具会读取的其他字段，见[组件文件格式](component-format.mdx)。

组件装好后，每项 `health` 检查各运行一次 `kubectl wait`。`wait` 的每一项各是一个参数，最后再加上 `--timeout=<timeout>`，例如：

```sh
kubectl wait --for=condition=Ready nodes.longhorn.io --all -n longhorn-system --timeout=60s
```

安装工具可以用自己的等待时间代替 `timeout`。例如 `zeabur-installer apply` 刚装完时最多等 5 分钟，`zeabur-installer doctor` 则用每项检查自己的 `timeout`。检查失败时，显示它的 `advice`。

## 测试用例

上面每条规则在 `conformance/select/` 都有一个用例。这个目录在仓库里，也包含在 `bundle.tar.gz` 中，所以固定某个 catalog commit 或版本的安装工具，读到的就是那个版本的用例。格式定义在 [`schema/v1/select-case.schema.json`](../../../schema/v1/select-case.schema.json)。

```yaml
description: A default not tested on the distribution is installed with a warning.
components:            # index.json components, with only the fields selection reads
  - id: traefik
    provides: {capability: ingress}
    defaults: {single-node: recommended, multi-node: recommended}
    testedOn:
      - {distribution: k3s, platforms: [linux/amd64]}
      - {distribution: rke2, platforms: [linux/amd64]}
      - {distribution: kubesolo, platforms: [linux/amd64]}
  - id: victoria-logs
    provides: {capability: logs}
    defaults: {single-node: recommended, multi-node: recommended}
    testedOn:
      - {distribution: k3s, platforms: [linux/amd64]}
      - {distribution: kubesolo, platforms: [linux/amd64]}
config:
  profile: multi-node
  distribution: rke2
  platform: linux/amd64
  # add: what the installer adds to the defaults
  # enable, disable: the person's lists
want:
  components:          # in install order
    - {id: traefik, why: default}
    - {id: victoria-logs, why: default}
  warnings:            # in any order
    - {kind: untested, component: victoria-logs, distribution: rke2}
  # leftOut: {<id>: {reason: …, …}}
  # error: {kind: unknown, name: …}, in place of the rest
```

运行用例的步骤如下。

1. 用 `components` 建立索引。每个组件的 capability 是它的 `provides.capability`。某个 profile 没有 `installOrder` 时，只装组件本身。
2. 按 `config` 选择组件。
3. 和 `want` 比对。`want` 没写的列表或映射就是空的。原因、警告和错误都比对代码和字段，不比对安装工具显示的文字。
