打上 `vX.Y.Z` tag 会发布 `index.json`、`bundle.tar.gz`、`checksums.txt`，以及各自的 Sigstore 签名包。使用 Zeabur Catalog 的工具应固定一个版本，验证后再读取 `index.json`。

## 版本产物

| 文件 | 内容 |
| --- | --- |
| `index.json` | 所有组件及其各个 profile 的安装顺序与测量数据、各个 capability 默认启用（recommended）的组件、所有模板及其测量数据、资源预算、Kubernetes 版本，以及 KubeSolo 上的个人安装提供什么（`kubesolo`）。profile 是 `single-node` 或 `multi-node` 的配置组合；capability 是用途类别。 |
| `bundle.tar.gz` | 软件包（bundle），包含索引、交叉检查数据、组件、模板及相关文件。 |
| `checksums.txt` | 文件的校验和。 |

每个发行文件都有一份 cosign 无密钥 Sigstore 签名包。`index.json` 对应的文件名是 `index.json.sigstore.json`。版本还附有 `SHA256SUMS`，每个文件都有 GitHub 构建来源证明（build provenance attestation）。

所有 zeabur-oss 版本都由 [zeabur-oss/.github](https://github.com/zeabur-oss/.github) 的共享发布工作流签名。签名会记录该工作流、仓库 `zeabur-oss/catalog` 和 tag。

## 验证并读取版本

<Steps>

<Step>

### 固定版本并验证签名

工具先固定要使用的版本，再验证文件。以下命令验证 `index.json`：

```sh
tag=vX.Y.Z
cosign verify-blob index.json --bundle index.json.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/zeabur-oss/\.github/\.github/workflows/release\.yml@' \
  --certificate-github-workflow-repository zeabur-oss/catalog \
  --certificate-github-workflow-ref "refs/tags/$tag" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

如果要改为检查来源证明，运行 `gh attestation verify index.json --repo zeabur-oss/catalog --signer-workflow zeabur-oss/.github/.github/workflows/release.yml`。

</Step>

<Step>

### 读取索引并生成安装内容

验证后，工具读取 `index.json`。只有不兼容的变更才会改动 `indexVersion`。

安装组件时，工具执行 `detection`，根据集群的 profile 提供默认启用（recommended）的组件，并向用户获取各组件的 `inputs`。接着按 `installOrder` 生成安装内容，将 `contributes` 合并到对应目标。

部署模板时，工具检查集群是否满足 `requires` 列出的所有要求，再向用户获取模板输入值，并将其余自动生成的值写入 Secret。接着按项目的 Namespace 渲染并应用 `manifests.yaml`。

部署操作见[部署模板](../get-started/deploy-a-template.mdx)。

</Step>

</Steps>

## 从 commit 构建版本产物

在任意 commit 执行：

```sh
nix build .#release
```

根据 `flake.nix`，`release` 输出包含：

- `index.json`
- `crosscheck.json`
- `bundle.tar.gz`
- `checksums.txt`

其中，`bundle.tar.gz` 包含：

- `index.json`
- `crosscheck.json`
- `components/`
- `templates/`
- `schema/`
- `config/`
- `measurements/`
- `LICENSE`
- `README.md`

这个命令会构建与发布版本逐字节相同的产物。工具可先从尚未发布的 commit 构建，等该 commit 发布后，再与已签名的版本比对。
