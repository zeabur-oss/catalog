把组件文件放在 `components/<capability>/<upstream>.yaml`，每个 capability（用途类别）与上游的组合各用一个文件。文件使用 YAML，包含通用结构、安装内容和配置。路径就是 ID，例如 `components/ingress/traefik.yaml` 的 ID 是 `ingress/traefik`。

## 通用结构

组件与模板共用 `apiVersion`、`kind`、`metadata` 和 `requires` 这组结构。`kind` 用来区分组件与模板，`requires` 可以填写 capability 或 `<capability>/<upstream>`。

```yaml
apiVersion: catalog.zeabur.com/v1
kind: Component                   # or Template
metadata:
  name: Traefik Proxy
  description: Why it is recommended, or what the template runs, in one or two sentences.
  license: MIT                    # SPDX
  homepage: https://traefik.io/traefik/
requires: [certificates]          # <capability> or <capability>/<upstream>
```

组件的 `metadata` 还有 `summary`：用一句平实的话说明它为集群提供什么，给挑选组件的人看，翻译放在 `locales`。安装工具显示的是 summary，description 留给运维人员。

```yaml
metadata:
  summary: Routes traffic from your domains to your services.
  locales:
    zh-TW: {summary: 把網域的流量導向你的服務。}
    zh-CN: {summary: 把域名的流量转发到你的服务。}
```

## 组件字段

下面是一个精简示例。`defaults` 指定各 profile（`single-node` 或 `multi-node` 的配置组合）的启用配置，`recommended` 表示默认启用（recommended）。`releases` 列出按顺序安装的内容，`profiles` 的配置会合并到共用的 `values`。

```yaml
apiVersion: catalog.zeabur.com/v1
kind: Component
metadata:
  name: Traefik Proxy
  description: Why it is recommended, in one or two sentences.
  license: MIT                    # SPDX; OSI-approved, or opt-in only (see below)
  homepage: https://traefik.io/traefik/
maturity: independent             # cncf-graduated | cncf-incubating | cncf-sandbox | kubernetes-sig | independent
defaults: {single-node: recommended, multi-node: recommended}
requires: [certificates]          # installed first
distributions: [k3s]              # optional; omitted means any cluster

releases:                         # installed in order
  - name: traefik
    namespace: traefik
    chart: oci://ghcr.io/traefik/helm/traefik   # or repo: https://… plus chart: <name>
    version: 41.7.1                             # exact; Renovate bumps it
    chartDigest: sha256:…                       # required with chart; see Digests
    values: |                                   # shared by every profile
      gatewayClass:
        # Every value has a comment saying why; `catalog validate` enforces it.
        enabled: true
      image:
        # Every image is <tag>@sha256:<digest>; `catalog render` enforces it.
        tag: v3.7.16@sha256:…
    profiles:                                   # merged over values like helm -f
      single-node: |
        deployment:
          # One node: a second replica gains nothing.
          replicas: 1
  - name: crds
    namespace: kube-system
    urls: [https://github.com/…/releases/download/{version}/standard-install.yaml]
    version: v1.6.2
    urlDigests: [sha256:…]                      # one per URL, in order
  # or: manifests: |  objects applied as written

inputs: []        # values to ask for or generate; Secrets are created from them
provides: {...}   # an in-cluster registry other software uses
resources: {...}  # memory it needs while working, on top of idle
internalCRDs: []  # CRDs of detection.crds whose objects it writes itself
networkPolicies: |  # traffic it needs where an installer isolates namespaces
contributes: []   # values added to another component's release (CrowdSec -> Traefik)
detection: {...}  # CRDs, API services, Helm charts, workloads
security: {...}   # RBAC summary, cluster-wide, privileged, podSecurity, egress, credentials, tenant risks
smoke: []         # extra e2e checks
leftovers: []     # what the upstream keeps on uninstall (e.g. CRDs)
```

## 安装工具读取的字段

这些字段告诉安装工具组件提供什么，安装工具不需要靠 ID 认出组件。

`provides.registry` 是集群里的 OCI registry：`host` 是镜像名称里的 `host:port`，`ca` 是存放签发其证书的 CA 的 Secret key。移除组件前，会等到其命名空间以外没有 Pod 在运行这个 host 的镜像。

输入设成 `generate: clusterIP`，就是给组件的某个 Service 指定固定的 ClusterIP。节点的容器运行时解析不了 registry 的 host，所以安装工具会从 Service CIDR 挑一个空闲地址填进去，并在每个节点配置 registry mirror 指过去。留空时（CI 就是这样），Kubernetes 会自动分配地址，只有 Pod 能访问 registry。

```yaml
inputs:
  - name: cluster-ip
    release: zot
    path: service.clusterIP
    generate: clusterIP
provides:
  registry:
    host: zot.zot.svc:5000
    ca: {name: zot-tls, key: ca.crt, namespace: zot}
```

`detection.csiDrivers` 列出组件提供的卷所用的 CSI driver。移除组件前，会等到没有 PersistentVolume 使用其中任何一个。要找对应的 StorageClass，看它的 `provisioner`。

移除组件前，也会等到其命名空间以外没有 `detection.crds` 的对象，但 `internalCRDs` 列出的除外：这些 CRD 的对象是组件自己写的，例如扫描报告。`internalCRDs` 的每一项都必须在 `detection.crds` 里。

`resources.workMemoryMiB` 是组件工作时（例如跑一次构建）在空闲用量之外还要多用的内存。空闲用量由 e2e 测量，放在 `index.json`。

`networkPolicies` 给默认拦截每个命名空间入站流量的安装工具用。内容是组件自己命名空间里的标准 NetworkPolicy 对象，这类安装工具会在安装 releases 前应用，放行组件需要从其他地方进来的流量。其他安装工具可以忽略它。`catalog validate` 会检查每个对象都是组件命名空间里的 NetworkPolicy。

## 用 digest 固定内容

每个 `releases` 条目都要用 digest 固定内容。chart 或 URL 的内容与 digest 不符时，Zeabur Installer 与 `catalog render` 会停止。

- HTTP chart 的 `chartDigest` 使用仓库 `index.yaml` 中对应条目的 `digest`，也就是 `.tgz` 的 sha256。
- OCI chart 的 `chartDigest` 使用 manifest digest，也就是 `helm push` 输出的值。`helm pull <chart>:<version>@sha256:…` 会检查这个值。
- `urlDigests` 使用每个下载文件的 sha256，顺序必须与 URL 一致。
- 镜像在 `values` 中使用 `<tag>@sha256:<digest>`，也包括 chart 通过参数传给 operator 的镜像。chart 无法接受 digest 时，要在 `unpinnedImages` 中列出镜像，并用注释说明原因。URL 安装条目不受这项要求限制。

Renovate 会更新镜像与 OCI chart 的标签和 digest。它无法读取 HTTP chart 或 URL 的 digest。Renovate 更新 `version` 后，`catalog render` 会失败，并输出新的 digest，供你复制填入。

安装结果必须一致：chart 不得生成密钥或证书。需要生成的值放在 `inputs` 中，并存储在 Secret 中；证书由 cert-manager 提供。如果两次渲染的结果不同，`catalog render` 会失败。

完整字段定义见[组件 JSON Schema](https://github.com/zeabur-oss/catalog/blob/main/schema/v1/component.schema.json)。
