---
title: 用 zeaburctl 部署範本
description: 用 zeaburctl 匯出範本的物件，檢查後再用 kubectl 套用。
---

`zeaburctl templates export` 會印出把 Zeabur Catalog 範本部署到 Zeabur 開源版專案時寫入的物件，和網頁介面寫入的相同。檢查這些物件，用 `kubectl` 套用，再執行煙霧測試（smoke check）和你自己的測試。指令的說明和給程式碼代理的提示詞見 [Zeabur 開源版文件](https://oss.zeabur.com/zh-TW/docs/zeabur/deploy/templates/)。

## 開始前

- 安裝 `kubectl`，以及和你的 Zeabur 開源版同版本的 `zeaburctl`。`zeaburctl` 內含 Zeabur 開源版所附 Zeabur Catalog 版本的範本。
- 閱讀範本 `template.yaml` 中的授權、輸入、`requires` 和安全風險。
- 使用會落實 NetworkPolicy 的 CNI。範本不限制對外流量。
- 如果範本需要網域，先準備好 cert-manager ClusterIssuer。
- 每個專案內，同一個範本只能安裝一次，因為範本內的物件名稱固定。

<Steps>

<Step>

### 檢查叢集

範本不指定 StorageClass，磁碟區會使用預設的 StorageClass。沒有預設 StorageClass 時，PersistentVolumeClaim 會停在 `Pending`。列出 StorageClass：

```sh
kubectl get storageclass
```

其中一行的名稱後面有 `(default)`，例如 `local-path (default)`。如果沒有，先把一個 StorageClass 設為預設再繼續。

</Step>

<Step>

### 匯出並套用範本

把 `<id>` 換成範本 ID，`app` 換成專案：

```sh
umask 077
zeaburctl templates export <id> --project app \
  --domain app.example.com --cluster-issuer letsencrypt --set <name>=<value> > app.yaml
kubectl diff --server-side -f app.yaml
kubectl apply --server-side -f app.yaml
```

範本要求的每個輸入都用 `--set <name>=<value>` 提供。沒提供的輸入、缺少的 `--domain` 和 `--cluster-issuer` 會以 `<name>` 預留位置出現，套用前要帶上這些值重新匯出。如果叢集缺少範本需要的元件，`zeaburctl` 會說明，並列出安裝它的 `zeaburctl components export` 指令。物件儲存貯體和認證資訊必須事先準備好。

輸出的開頭是存放範本自動產生的密碼和金鑰的 Secret。每次匯出都會產生新值，所以只匯出一次，並套用那個檔案。再套用之後的匯出，會換掉執行中應用程式的密碼。不要把這個檔案加入版本控制。

確認每個 Pod 都有啟動：

```sh
kubectl -n app get pods
```

幾分鐘內，每個 Pod 的 `STATUS` 會是 `Running`，`READY` 的兩個數字相同，例如 `1/1`。已完成的 Job 的 Pod 會顯示 `Completed`。接著執行 `template.yaml` 中 `smoke` 列出的檢查，以及你自己的測試。範本有網域時：

```sh
curl -sI https://app.example.com | head -n 1
```

第一行是 HTTP 狀態列，例如 `HTTP/2 200`。

</Step>

<Step>

### 升級與回滾

記錄每次部署的版本、專案、映像檔參照、輸入和 Secret 名稱。升級前，先比較匯出的物件差異，再閱讀目前版本到目標版本之間的所有升級注意事項。接著完成備份，並在複本上演練升級。

要把應用程式回滾到舊版，先確認資料庫和儲存空間的相容性，再套用先前已驗證版本的物件。資料庫降版通常需要還原。備份應存放在應用程式的專案之外。

</Step>

</Steps>

## 自動產生的輸入

自動產生的輸入包含 `secret`（`name` 和 `key`）和 `validation.pattern`。產生的值必須完整符合 `validation.pattern`。

| 欄位 | 說明 |
| --- | --- |
| `generate.type` | `random`。 |
| `generate.bytes` | 編碼前的隨機位元組數，範圍為 12 到 64，必填。 |
| `generate.encoding` | `base64url`（不含填補字元）或小寫 `hex`，必填。 |

使用者提供的輸入包含 `required`，不包含自動產生欄位。12 個位元組用 `base64url` 編碼後會得到 16 個字元。16 或 32 個位元組用 `hex` 編碼後，會分別得到 32 或 64 個字元。

CloudNativePG 會自行建立存放應用程式認證資訊的 Secret，範本直接沿用。
