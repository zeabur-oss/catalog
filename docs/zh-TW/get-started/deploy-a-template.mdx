先驗證版本簽章，再用 `catalog` 指令渲染並套用範本。最後執行範本的煙霧測試（smoke check），再執行你自己的測試，確認部署結果。

## 開始前

- 使用你信任的原始程式碼 checkout，以你要部署的 tag 建置 `catalog` 指令。不要執行未驗證的下載檔。
- 安裝範本 `requires` 列出的每個元件，全部使用同一個版本。
- 使用會落實 NetworkPolicy 的 CNI。安裝程式會隔離各專案的 Namespace。範本不限制對外流量。
- 把一個 StorageClass 設為預設。範本不指定 StorageClass，磁碟區會使用預設值。沒有預設 StorageClass 時，PersistentVolumeClaim 會停在 `Pending`。
- 如果範本需要網域，先準備好 cert-manager ClusterIssuer。
- 每個 Namespace 內，同一個範本只能安裝一次，因為範本內的物件名稱固定。

<Steps>

<Step>

### 驗證版本

先建立私有目錄，把同一個版本 tag 的 `bundle.tar.gz` 和 `bundle.tar.gz.sigstore.json` 下載到裡面。再依工作流程、儲存庫和 tag 驗證簽章：

```sh
tag=vX.Y.Z
cosign verify-blob bundle.tar.gz --bundle bundle.tar.gz.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/zeabur-oss/\.github/\.github/workflows/release\.yml@' \
  --certificate-github-workflow-repository zeabur-oss/catalog \
  --certificate-github-workflow-ref "refs/tags/$tag" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

如果只檢查簽發者或工作流程，驗證時也會接受其他工作流程或其他 zeabur-oss 儲存庫的簽章。簽章驗證通過後，才能解開套件包（bundle）。解開時必須拒絕絕對路徑、`..` 和連結。

</Step>

<Step>

### 渲染並套用範本

先閱讀 `templates/<id>/template.yaml` 中的授權、輸入、`requires`、安全風險、擴充限制和升級注意事項，再渲染物件：

```sh
go run ./tools/cmd/catalog template render -namespace app \
  -domain app.example.com -cluster-issuer letsencrypt -values inputs.json <id> > plan.yaml
```

`inputs.json` 是一個 JSON 物件，範本要求的輸入都要填入字串值。物件儲存貯體和認證資訊必須事先準備好。

產生包含範本密碼和金鑰的 Secret，再套用物件：

```sh
umask 077
go run ./tools/cmd/catalog template inputs -namespace app <id> > secrets.json
kubectl create namespace app
kubectl -n app apply -f secrets.json
kubectl -n app apply -f plan.yaml
```

不要把 `secrets.json` 加入版本控制。每次執行 `inputs` 都會產生新值，所以每次部署只執行一次，升級時沿用既有的 Secret。

套用完成後，執行一次範本附的煙霧測試，也要執行你自己的測試。

</Step>

<Step>

### 升級與回滾

記錄每次部署的版本、Namespace、映像檔參照、輸入和 Secret 名稱。升級前，先比較渲染後的物件差異，再閱讀目前版本到目標版本之間的所有升級注意事項。接著完成備份，並在複本上演練升級。

要把應用程式回滾到舊版，先確認資料庫和儲存空間的相容性，再部署先前已驗證版本的物件。資料庫降版通常需要還原。備份應存放在應用程式的 Namespace 之外。

</Step>

</Steps>

## 自動產生的輸入

自動產生的輸入包含 `secret`（`name` 和 `key`）和 `validation.pattern`。產生的值必須完整符合 `validation.pattern`。

| 欄位 | 說明 |
| --- | --- |
| `generate` | `random`。 |
| `generateBytes` | 編碼前的隨機位元組數，範圍為 12 到 64，預設為 32。 |
| `generateEncoding` | `base64url`（預設，不含填補字元）或小寫 `hex`。 |

使用者提供的輸入包含 `required`，不包含自動產生欄位。12 個位元組用 `base64url` 編碼後會得到 16 個字元。16 或 32 個位元組用 `hex` 編碼後，會分別得到 32 或 64 個字元。

CloudNativePG 會自行建立存放應用程式認證資訊的 Secret，範本直接沿用。
