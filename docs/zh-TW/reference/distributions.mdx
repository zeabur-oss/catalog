---
title: 各 Kubernetes 發行版的差異
description: 比較各 Kubernetes 發行版的已知差異，確認元件與範本需要哪些設定。
source: "46ee823c91b3"
---

元件與範本都在 kind 上測試。測試使用的 Kubernetes 小版本，與 Zeabur Installer 固定使用的 RKE2 版本相同。`single-node` profile 使用 1 個節點，`multi-node` profile 使用 3 個節點。這兩個 profile 分別定義這兩種部署方式的設定。元件也會在 runner 上安裝的 k3s、RKE2 與 KubeSolo 上測試（見[測試與 CI](../contribute/tests.mdx)）。其他發行版的行為相同，但有以下已知差異。

- **k3s**：啟動時加上 `--disable=traefik,metrics-server`，讓 Traefik 與 metrics-server 都由各自的 chart 安裝。k3s 會安裝自己的 Gateway API CRD。在 NAT 後方執行時，不要設定 `node-external-ip`，否則 Traefik 會失去用戶端位址。
- **KubeSolo**：刪除 PersistentVolumeClaim 後，預設 StorageClass 仍會保留磁碟區及其資料。在 Ubuntu 上，請將 `/etc/hosts` 中的主機名稱對應到節點 IP。若對應到 127.0.1.1，API server 會拒絕代理連線至 kubelet。KubeSolo 的節點沒有 control-plane 標籤。
- **Longhorn**：每個節點都需要安裝 open-iscsi、啟動 `iscsid`，並具備 `iscsi_tcp` 模組與 NFSv4 用戶端。不要讓 multipathd 管理 Longhorn 使用的磁碟。詳細需求請看 Longhorn 元件檔案中的註解。
- **發行版限制**：元件的 `distributions` 欄位列出元件只能在哪些發行版上執行，用來表示硬性限制，例如其他發行版不會設定的節點標籤。例如，system-upgrade-controller 只能在 k3s 與 RKE2 上執行。在 k3s、RKE2 與 KubeSolo 上執行 e2e 測試時，如果清單沒有列出該發行版，就會略過這個元件。元件通過測試的發行版，記錄在 `index.json` 的 `testedOn`。
- **範本儲存空間**：範本不指定 StorageClass，因此磁碟區會使用叢集的預設 StorageClass。若叢集沒有預設 StorageClass，PersistentVolumeClaim 會停留在 `Pending`。
